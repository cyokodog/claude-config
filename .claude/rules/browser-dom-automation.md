# 他サイトの画面を操作するコードは、実 DOM を読んでから書く

拡張の content script や自動入力など、他社サイトの画面を操作するコードを書く・直すときに適用する。

- セレクター・ラベル・画面の流れを推測で書かない。書く前に、対象の操作の**前後すべての状態**（選択用の別画面、アップロード後、保存後、エラー時）の実 DOM を読む。1 画面だけ見て残りを想像で埋めない。
- 読み取りはユーザーの作業タブに触れず、確認用のタブで行い、終わったら閉じる。フォームへの入力・アップロード・保存など副作用のある確認は、ユーザーの了承を得てから行う。
- 実 DOM を読めない状態（ログインが必要、操作の後でしか現れない）なら、推測で実装を進めず、その状態の HTML の抜き出しをユーザーに頼むか、了承を得て確認する。
- テストの疑似 DOM は、読んだ実 DOM の構造を写して作る。推測の DOM で通ったテストを動作の根拠にしない。
- 実画面で失敗したら、まず失敗した時点の DOM を確かめる。原因を確かめずに直しを重ねない。

背景：2026-10-26、メルカリの出品画面への入力処理を推測のセレクターで書き、カテゴリー末端の確定・空の `role="dialog"`・入力途中の復元の 3 点で実画面の確認を 3 回失敗させた（cyk-mercari-post の `docs/worklog/2026-10-26.md`）。
