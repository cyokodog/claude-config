# 個人プロジェクトの進め方と、学びの残し方

対象: リポジトリのオーナーが `cyokodog` の個人プロジェクト（`gh repo view --json owner`）。仕事のプロジェクトには適用しない。

## 進め方

相談で方向が決まり、ユーザーが「issueにして」「進めて」などと言ったら `cyk-gh-flow-lite` スキルで回す。
承認は 2 回（Issue の作成時、マージの前）だけで、あとは止まらずに進める。

## ローカルで動かすアプリのポート

個人アプリのポートは `~/raycast-scripts/my-apps.conf` で一元管理している（Raycast の `my-apps.sh` がここから起動する）。新しいプロジェクトでサーバー・開発サーバーのポートを決めるときは、先にこのファイルを読み、登録済みの番号と重ならないものを選んで、同じ形式（名前・ディレクトリ・起動コマンド・ポート・URL）で登録する。引き継いだプロジェクトで未登録のポートを見つけたときも、重なりを確認して登録する。

## 学びの仕分け

知見の抽出・保存先・目次更新は `~/src/github.com/cyokodog/claude-config/.claude/shared/cyk-knowledge-recording.md` を共通の定義として使う。通常のGHフローもライト版も同じ手順を参照する。

通常版はPR作成前、ライト版は既存のマージ前承認ゲートで候補と保存先を提示し、承認された範囲で保存する。作業経緯は各フローのIssue・worklogの記録手順に従う。コミット・プッシュはユーザーの明示的な指示に従う。
