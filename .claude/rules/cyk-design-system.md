# 個人プロジェクトの UI は cyk-design-system を使う

個人プロジェクト（オーナーが `cyokodog`）で画面を作る・直すときは、自作の見た目を書く前に [cyk-design-system](https://github.com/cyokodog/cyk-design-system)（`~/src/github.com/cyokodog/cyk-design-system`、非公開）を使う。仕事のプロジェクトには適用しない。

- 構成は React + Vite を基本にする。参照は ghq の並びを前提に `file:` の相対パス（例: `"cyk-design-system": "file:../cyk-design-system"`）。
- **Vite に `resolve: { dedupe: ['react', 'react-dom'] }` を必ず書く。** `file:` はシンボリックリンクになり、デザインシステム側の React まで読まれてフックが壊れるため。
- 入口で `cyk-design-system/style.css`（必須）と `cyk-design-system/fonts.css`（任意）を読み、ルート要素に `cyk-root` クラスを付ける。
- 色・余白・文字サイズは `--cyk-*` の CSS 変数で書き、値を直書きしない。ライト・ダークは OS 設定に従う。
- 部品が足りないとき、他のプロジェクトでも使えそうならデザインシステム側に足す（その README の「部品を足すとき」に従う）。そのプロジェクト専用ならプロジェクト側に書く。
- 使い方の詳細はデザインシステムの `README.md` を読む。

## 新規プロジェクトとデザイン提案での適用

このルールは画面ファイルの編集時だけでなく、新規プロジェクトの基盤構築とUIの要件整理・デザイン提案の段階でも明示的に読む。上の `paths` はファイル編集時の適用条件であり、それ以前の確認を省く条件ではない。

- 提案前に `cyk-design-system` の `README.md`、`src/components/`、`preview/`（部品カタログと参考パターン）を確認し、近い参考パターンがあればそれを土台に、既存部品で案を組み立てる。
- 提案では、参考にしたパターン、再利用する既存部品、不足する共通部品、対象プロジェクト専用の画面構成を示し、それぞれの配置先を明記する。
- 置き場所の区別:
  - **正式な画面デザインは対象プロジェクトに置く。** 画面案は対象プロジェクトの `design/` に、デザインシステムの部品とダミーデータで組む。`cyk-design-system` にプロジェクトごとのディレクトリや画面案を作らない。
  - **`cyk-design-system` には汎用の部品と参考パターンだけを置く。** 参考パターンは実際のプロジェクトの画面から組み合わせ方だけを取り出した写しで、正本ではない。足し方は `cyk-design-system` の README「パターンを足すとき」に従う。
- 実装後は、共通部品と見本の反映先、ライト・ダークの確認結果を報告する。追加する共通部品がなければ、使った既存部品を報告する。
- 実装後（cyk-gh-flow-lite ではマージ前の承認時）に、他のプロジェクトでも使えそうな画面の組み合わせがあれば、参考パターンとして `cyk-design-system` に足す候補を示す。足すのはユーザーが承認したものだけにする。
- 基盤だけを依頼された場合も、この利用方針を説明する。ただし、デザインルールの確認を理由に、未依頼の画面実装へ進まない。
