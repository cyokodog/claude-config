# cyk-tmux-context-handoff

## 前提

- 現在のシェルが tmux セッション内で動作していること（`$TMUX` が設定されていること）を確認する
- これは `claude --continue` / `claude --resume` の代替ではない。新しいペインで起動する Claude は完全に独立した新規セッションであり、現セッションのログファイルを**データとして読ませる**ことで文脈を把握させる

## 手順

### 1. ユーザーへの確認（必須・スキップ不可）

このスキルが自動でトリガーされた場合（Claude が長い会話を見て提案する場合）も、ユーザーが明示的に依頼した場合も、**実行前に必ず一度確認する**。新規プロセスの起動とペイン作成という後戻りしにくい操作を、確認なしで実行しない。

- 引き継ぎを今実行してよいか
- ペインの分割方向（垂直 `-v` / 水平 `-h`。デフォルトはユーザーに聞く。過去に選択があればそれを踏襲してよい）
- ログをそのまま読ませるか、要約を作ってから渡すか（下記2参照）

### 2. 引き継ぎ方式の選択

| 方式           | 内容                                                                                     | 適する場面                                               |
| -------------- | ---------------------------------------------------------------------------------------- | -------------------------------------------------------- |
| 生ログ読解     | セッションのjsonlログファイルをそのまま新セッションに読ませる                            | 会話量がそれほど多くない、詳細な経緯も引き継ぎたい       |
| 要約ハンドオフ | 現状の要点（決定事項・現在の状態・次にやること）を短いMarkdownファイルにまとめてから渡す | 会話が非常に長く、生ログを読ませるとコスト・時間がかかる |

要約ハンドオフを選んだ場合、スクラッチディレクトリに `handoff-<日付>.md` のようなファイルを作成し、以下を簡潔に書く：

- これまでの主な決定事項
- 現在の作業状態
- 次にやるべきこと

### 3. 現在のセッションログの特定

```bash
# 現在の作業ディレクトリを "/" → "-" に置換したものが projects 配下のディレクトリ名になる
PROJECT_DIR=$(echo "$PWD" | sed 's/\//-/g')
ls -t "$HOME/.claude/projects/$PROJECT_DIR"/*.jsonl | head -5
```

- 最も新しい更新日時のファイルが現在のセッションのログである可能性が高いが、**同一プロジェクトで複数セッションが同時に動いている場合はこの推定が外れる**
- 複数の候補があって迷う場合や自信が持てない場合は、ユーザーにどのログファイルか確認する
- 要約ハンドオフを選んだ場合、この生ログパスの特定は要約作成のための参照用として使う

### 4. tmuxで新規ペインを作成

新しいペインのIDを確実に取得するため、`-P -F` オプションでIDを出力させる：

```bash
# 垂直分割（上下）の場合
NEW_PANE=$(tmux split-window -v -P -F '#{pane_id}')

# 水平分割（左右）の場合
NEW_PANE=$(tmux split-window -h -P -F '#{pane_id}')
```

### 5. 新規ペインでClaude Codeを起動し、ログ/要約を読ませる

`tmux send-keys` で対象ペイン（`$NEW_PANE`）にコマンドを送る。ファイルパスや指示文にシェル上特別な文字（引用符など）が含まれる可能性があるため、パスは変数に入れてクォートを剥がさないよう注意する。

```bash
LOG_PATH="/path/to/session.jsonl"   # または要約ファイルのパス
tmux send-keys -t "$NEW_PANE" "claude \"このログファイルを読んで、これまでの会話の文脈・決定事項・現在の状態を理解してください: $LOG_PATH\"" Enter
```

- 生ログを渡す場合は「このjsonlログを読んで文脈を理解して」という趣旨の指示にする
- 要約ハンドオフの場合は「この引き継ぎメモを読んで状況を理解して」という趣旨にする
- `claude --continue` や `claude --resume` は使わない（独立した新セッションにする）

### 6. 元ペインへの報告

新規ペイン作成・Claude起動・渡したログ/要約ファイルのパスを元のペインでユーザーに報告して完了する。
