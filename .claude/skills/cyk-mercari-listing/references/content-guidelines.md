# 原稿と調査のガイド

商品担当が原稿を作るとき、メインが追加調査を行うときに参照する。

## 商品の特定と事実

- 写っている文字・ロゴ・型番ラベル・パッケージを根拠にする。人物を模した商品でも、顔立ちから人物名を推定せず、文字の手がかりかユーザーへの質問で確認する。
- 型番・正式名称が曖昧なら候補と根拠を返し、必要な資料を確認する。購入時期・使用頻度・動作・欠品・傷の有無を画像だけで断定しない。
- 箱や説明書が写っていることと、実際に付属することは分ける。写真にないものを欠品とも断定しない。
- 最初の画像の背景の写り込みや不足する角度（型番ラベル・操作部・傷のアップなど）は原稿確定前にメインへ伝える。
- ユーザー確認済み・画像で確認・資料で確認・推測を区別し、未確認の仕様や機能を事実として説明文へ入れない。

## 5項目の原稿

- 画像：ユーザーが指定した商品ごとの順序を維持する。先頭をサムネイルとして提案し、入れ替える理由があれば確認する。
- 商品名：初期案は40字以内。ブランド・商品名・型番・サイズなど検索される語を前に置く。【美品】などは確認済みの状態に見合う場合のみ使う。
- カテゴリー：候補の階層名は提案できるが、IDは実装済みアプリの一覧でメインが解決する。近いものへ独断で置き換えない。
- 商品の状態：既存選択肢と契約を確認して提案する。傷・汚れ・動作について必要な回答がない場合は質問を返す。
- 説明：商品概要→状態→付属品→サイズ・仕様→ハッシュタグを基本に、商品に必要な要素だけを書く。ハッシュタグ込み1000字以内を初期案の目安とし、実際の上限はメインがアプリ契約で確認する。

誰が何のために買うか（実用品、ディスプレイ品、部品取り・修理ベース、コレクション品など）を踏まえて冒頭を組む。魅力を伝えるために未確認の年代・性能・状態を足さない。

- 発送・梱包方法、喫煙者・ペットの有無は書かず、後者は質問もしない。
- 実寸が不明なら「実寸が必要な方はコメントいただければお測りします。」とする案を出せるが、ユーザーが測定に対応するか未確認なら、その対応を既定の約束として確定しない。
- 不具合は、使える機能と使えない機能を項目ごとに具体的に書く。見た目だけの推測は「写真をご確認ください」に寄せる。
- ハッシュタグは表記ゆれ（英字・カタカナ・略称）、型番・シリーズ、カテゴリー、関係する用途語を優先する。商品と無関係な人気タグは入れず、字数が足りなければ優先度の低いものを削る。
- 価格・配送・ブランド等の専用欄は今回の入力対象外。説明文にブランド名を書くことと、対象外のブランド欄を入力することは区別する。

## 追加調査を頼まれた場合

相場・価格検討は5項目の作成に常時必須の工程にしない。ユーザーが希望した場合に、商品を同定してから調査する。

- 商品URLをキーに重複を除き、商品名・価格・売却状況・状態・セット内容など必要な情報を一度取得して再利用する。全ページの再取得を繰り返さない。
- 型番違い・別サイズ・ジャンク・セット販売・同シリーズの別グッズなどは比較対象から分ける。判別できないものだけ追加確認する。
- 売り切れ商品の価格と、出品中の同商品の件数・価格を分けて示す。出品中の高値を売れた相場と扱わない。高値の理由が確認できた場合のみ補足する。
- 集計は計算手段で行い、件数・中央値・範囲・除外理由を短く返す。メインが利用できるアプリの集計機能は、実装確認後にだけ使う。
- 通常取得で不足した場合のブラウザ閲覧は、メインが `~/src/github.com/cyokodog/claude-config/.claude/shared/cyk-browser-operations.md` を読み、共通入口から行う。商品の担当ごとに同じブラウザを並行操作しない。
- 未調査・接続不可・標本が少ない場合はその限界を明示する。調査済みと推測しない。
