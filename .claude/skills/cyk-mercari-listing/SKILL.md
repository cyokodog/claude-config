# メルカリ出品下書きスキル

商品画像から出品内容を作り、ユーザーと詰めてから、メルカリの出品画面に入力する。

## 鉄則

- **ユーザーが承認するまでブラウザに入力しない。** 内容はまずターミナルで確認する。
- **「出品する」ボタンは絶対に押さない。** 「下書きに保存する」も押さない。押すかどうかはユーザーが決める。
- 画像から読み取れないこと（購入時期・使用頻度・傷の有無・付属品の欠品など）は推測で書かない。ユーザーに聞く。

## 流れ

```
Step 1 画像を受け取る
Step 2 商品の特定（対話）
Step 3 相場調査（ブラウザで閲覧のみ）
Step 4 出品内容の提案（ターミナル）
Step 5 補正（ユーザーの指示で直す。承認まで繰り返す）
Step 6 出品画面への入力（承認後のみ）
Step 7 引き渡し
```

## Step 1: 画像を受け取る

受け取り方は次のどちらでもよい。

- **会話に貼られた画像**: そのまま見る。`[Image: source: <パス>]` が付いていれば、そのパスを Step 6 のアップロードに使う。パスが付いていない画像（クリップボードからの貼り付けなど）は、Step 6 の前にファイルの場所をユーザーに聞く
- **`$ARGUMENTS` の画像パスかフォルダ**: それを使う

どちらも無ければ、ユーザーに画像を求める。画像は1回にまとめて貼られるとは限らないので、「画像は以上です」と言われるか、こちらから確認してから Step 2 に進む。

- フォルダの場合は `jpg` / `jpeg` / `png` / `heic` / `webp` を列挙する
- `heic` は Read で読めないことがあるので、`sips -s format jpeg <in> --out <scratchpad>/<name>.jpg` で変換してから読む。変換したファイルは scratchpad に置き、元の画像はアップロード時にも元のパスを使う（メルカリは heic 非対応のため、変換後の jpg を使う）
- 全画像を Read で見る。メルカリの画像上限は20枚。超える場合はどれを使うかユーザーに聞く

## Step 2: 商品の特定（対話）

画像から読み取れたことを、確度つきで箇条書きにしてユーザーに確認する。

```
画像から読み取れたこと:
- 商品: 〇〇（ブランド名 / 型番 XXXX）… ロゴと型番シールから。確度 高
- 色: ネイビー
- 付属品: 箱・説明書が写っている。充電ケーブルは写っていない
- 状態: 角に擦れらしきものがある（3枚目）

確認させてください:
1. これは「〇〇 XXXX」で合っていますか？ 2020年モデルの △△ との可能性もあります
2. 使用期間・使用頻度はどのくらいですか？
3. 3枚目の擦れ以外に、傷・汚れ・動作不良はありますか？
4. 充電ケーブルは付属しますか？
```

- 商品の特定は、写っている文字・ロゴ・タグ・パッケージを手がかりにする。人物を模した商品（フィギュア・ブロマイドなど）でも、顔立ちから誰かを推定しない。誰のグッズかは、文字などの手がかりで絞るか、ユーザーに聞く
- 型番・正式名称が曖昧なときは、Web検索で候補を絞ってから確認する
- 1往復で埋まらなければ、何往復してもよい。商品が確定するまで Step 3 に進まない
- 写真の質もこの時点で伝える。1枚目（サムネイル）の背景の写り込み、足りない角度（開閉部・操作部・型番ラベル・傷のアップなど）を指摘し、撮り直し・追加するか聞く。入力の後に言っても遅い

## Step 3: 相場調査

Claude in Chrome でメルカリの**売り切れ**商品を検索し、相場を把握する。この Step ではページの閲覧だけをし、何も入力・クリックで変更しない。

1. ToolSearch で Claude in Chrome のツールをまとめて読み込む:
   `select:mcp__claude-in-chrome__tabs_context_mcp,mcp__claude-in-chrome__tabs_create_mcp,mcp__claude-in-chrome__navigate,mcp__claude-in-chrome__get_page_text,mcp__claude-in-chrome__read_page,mcp__claude-in-chrome__find,mcp__claude-in-chrome__computer,mcp__claude-in-chrome__form_input,mcp__claude-in-chrome__file_upload,mcp__claude-in-chrome__javascript_tool`
2. `tabs_context_mcp` → `tabs_create_mcp` で新しいタブを作る
3. 売り切れ検索 URL を開く（キーワードは URL エンコードする）:
   `https://jp.mercari.com/search?keyword=<キーワード>&status=sold_out&sort=created_time&order=desc`
4. `get_page_text` で商品名と価格を拾う。型番違い・ジャンク・セット売りは除外する
5. キーワードを変えて2〜3回検索する（型番だけ / 商品名＋ブランド / カタカナ表記 など）
6. 出品中（`status=on_sale`）も必ず見て、同じ商品が何件・いくらで出ているか（供給）を把握する
7. 検索結果は描画が遅れて `get_page_text` が空になることがある。そのときは `javascript_tool` で数秒待ってから `li[data-testid="item-cell"]` の `innerText` を集める
8. 相場から外れて高い出品中の品は、理由（整備済み・未使用・付属品完備など）をタイトルから読み取って添える。売れていない出品の価格を相場とみなさない

まとめ方:

```
相場（売り切れ 直近 N件）:
- 中央値 ¥X,XXX / 範囲 ¥X,XXX〜¥X,XXX
- 状態が良い・付属品完備のものは ¥X,XXX 前後
- 出品中の競合: ¥X,XXX〜（N件）
```

Claude in Chrome に接続できない場合は、相場調査を飛ばしたことを明示し、価格は「未調査」としてユーザーに決めてもらう。

## Step 4: 出品内容の提案

### 売り方を先に決める

文面を書く前に、「誰が何のために買うか」を決める。事実を並べるだけの説明文にしない。

- 状態と相場から、実用品／レトロ・ディスプレイ品／部品取り・修理ベース／コレクション品のどれとして売るか決める（両方の面があれば両方）
- 決めた売り方に合わせて、タイトルの語・説明文の冒頭・ハッシュタグを選ぶ。例: 一部機能が壊れた古い家電なら、冒頭で見た目・年代の魅力（「平成レトロ」「飾って楽しめる」）を出し、まだ使える機能を差別化点として続ける
- 売り方は提案の冒頭で一言示し、ユーザーの意図とずれていないか確かめる

以下の形式でターミナルに出す。

```
■ タイトル（NN/40字）
〇〇〇〇

■ 説明文（NNN/1000字 ※ハッシュタグ含む）
（本文）

#タグ1 #タグ2 ...

■ カテゴリ
大 > 中 > 小

■ ブランド
〇〇（メルカリのブランド候補に出る表記）

■ 商品の状態
目立った傷や汚れなし  ← 6段階から選ぶ

■ 商品の特徴（カテゴリによって出る任意項目。分かるものだけ）
- サイズ: 26.5cm
- メインカラー: ブルー
- 汚れ・破れ・臭いなど: あり

■ 価格
¥X,XXX
（根拠: 相場の中央値 ¥X,XXX、出品中の競合の状況）
手取り: 価格 ¥X,XXX − 手数料10% ¥XXX − 送料 約¥XXX（らくらくメルカリ便 NNサイズ想定）= 約¥X,XXX

■ 発送元の地域（出品画面で空欄になりがちなので、ここで聞いておく）
〇〇県
```

### タイトル

- 40字以内。検索される語（ブランド・商品名・型番・色・サイズ）を前に寄せる
- 【美品】などの装飾は、状態がそれに見合うときだけ使う

### 説明文

- 構成: 商品の概要 → 状態（傷・使用感を具体的に）→ 付属品 → サイズ・仕様 → ハッシュタグ
- 発送についての記述（梱包方法など）は入れない
- 喫煙者・ペットの有無は書かない（Step 2 でも聞かない）
- 実寸（着丈・身幅など）が分からないときは、サイズ欄に「実寸が必要な方はコメントいただければお測りします。」と添える
- Step 2 でユーザーから聞いたことだけを書く。画像から推測した状態は「写真をご確認ください」に寄せる
- 状態に限らず、仕様・付属品・対応機能も、画像・ユーザーの回答・調べた資料で確かめたことだけを書く。「ACアダプターは別売」「〇〇にも対応」のような推測を事実として書かない。確かめていないことは書かないか、ユーザーに確かめてもらう
- 機能に不具合がある場合も、何ができて何ができないかを項目ごとに書く（「早送り：できません」）

### ハッシュタグ

検索に引っかかる範囲を広く取る。説明文の末尾にまとめ、`#` の前に半角スペースか改行を入れる。

- **表記ゆれを両方入れる**: 英字とカタカナ（`#Nintendo #ニンテンドー #任天堂`）、略称と正式名（`#スイッチ #NintendoSwitch`）
- **型番・シリーズ名**: `#HAC001` `#有機ELモデル`
- **カテゴリ語**: `#ゲーム機` `#家庭用ゲーム`
- **関連ワード**: 用途・シーン・一緒に探されやすいもの（`#プレゼント` `#子供` `#マリオカート` など、商品と関係があるもの）
- 商品と無関係な人気タグは入れない（メルカリの規約で禁止されている）
- 説明文の字数（1000字）を超えないよう、優先度の低いタグから削る

### 商品の特徴

カテゴリを選ぶと出る任意項目（サイズ・メインカラー・モデル名・タレント名など）。購入者の絞り込み検索に使われ、空欄だとその条件で絞り込んだ人の検索結果に出ない。

- Step 2 で分かっていることから埋められるものは提案に入れる（特にサイズ・色）
- 選択肢に該当が無いもの（モデル名に該当モデルが無いなど）は空欄にする
- どんな項目が出るかはカテゴリ次第なので、提案時点で分からない項目は Step 6 で見つけ次第ユーザーに聞く

### 配送

提案には出さない。設定は次のとおり固定する。

- 配送料の負担: **常に送料込み（出品者負担）**
- 発送までの日数: **常に「4~7日で発送」**
- 配送の方法: **常に「らくらくメルカリ便」**
- 発送元の地域: 出品画面の既定値のまま。ただし空欄のことが多いので、Step 4 の提案で先に聞いておく

### 価格

- 相場を根拠に提案する。早く売りたい／高く売りたいの意向が分からなければ、両方の価格を出して選んでもらう
- 送料込みなので、送料ぶんを価格に織り込む。手数料10%と送料の見込みを引いた手取り額まで出す。送料は梱包後のサイズ（3辺合計）を見込んで、らくらくメルカリ便の料金を Web で確かめる（2026年10月時点: 60サイズ ¥750、80サイズ ¥850）。サイズが際どいときは両方の手取りを出す
- **売り切れ相場だけで決めない。出品中の同じ商品の数と価格（供給）を必ず見る。** 出品中がほとんど無ければ、売り切れ相場の上の方を狙える。安値の出品が多ければ、それに合わせる
- 出品中の比較では、同じ種類の商品だけを数える。名前が似ている別の商品（同じシリーズのキーホルダー版、セット売りなど）を競合に含めない。タイトルで判別できないものは、商品ページを開いて確かめる

## Step 5: 補正

ユーザーの指示（「タイトルにサイズ入れて」「価格もう少し強気で」など）で直し、**変更した項目だけでなく全体を出し直す**。

「これで入力して」「OK」など、ブラウザ入力への明確な承認があるまで繰り返す。承認があいまいなら確認する。

## Step 6: 出品画面への入力

承認後のみ行う。

1. Step 3 のタブ（無ければ新しいタブ）で `https://jp.mercari.com/sell/create` を開く
2. ログインしていなければユーザーにログインを頼んで待つ。ログイン操作は代行しない
3. `read_page` / `find` でフォームの構造を確認しながら、以下の順に入力する。セレクターは決め打ちせず、毎回ページを読んで要素を特定する
   1. 画像: `file_upload` で `input[type=file][data-testid="photo-upload"]` にアップロードする（1枚目がサムネイルになるので、Step 1 で決めた順に）
      - `file_upload` はセッションが読めるファイルしか受け付けない。外部ボリュームなどで拒否されたら、scratchpad の `mercari/` に `cp` してからそのパスを使う
      - **アップロードの前に**、画面上部の「商品名と説明文を自動入力」トグルを確かめる。最初からオンになっていることがあるので、オンなら `computer` の実クリックでオフにして、ズームで確認する（AIに商品名・説明文を書かせない）
      - `input[type=file]` はアクセシビリティツリーに出ないことがある。`find` で「photo upload file input」を探すと ref が取れる
      - アップロード後に「出品画像」ダイアログが出たら「次へ」、「AI出品サポート」ダイアログが出たら「スキップ」を押す。出ないこともある
   2. カテゴリ: 「カテゴリーを選択する」を開くと、画像から推定した候補が上部に「こちらのカテゴリーですか？」として出ることがある。提案に合う候補があればそれを選び、無ければ階層を順にクリックして選ぶ。カテゴリ構成は変わることがあるので、提案と名前が違えば一番近いものを選び、Step 7 で報告する（2026年10月時点の例: お笑い芸人は「ゲーム・おもちゃ・グッズ > タレントグッズ > タレント・お笑い芸人」、ラジカセは「テレビ・オーディオ・カメラ > オーディオ機器 > ラジオ・コンポ > ラジオ・ラジカセ」）
      - `javascript_tool` での `.click()` だと画面遷移しても選択が確定しないことがある。カテゴリ・ブランド・状態・メインカラーなど、別画面で選ぶ項目は `computer` の実クリックで選ぶ
      - カテゴリ選択直後に「出品する商品の選択（製品情報を入力する）」画面が出ることがある。「出品画面に戻る」を押す
   3. ブランド: 欄があれば入力して候補から選ぶ（カテゴリによっては欄が無い）。カタカナで出なければ英字でも検索する（「ソニー」では出ず「SONY」で出た）
   4. 商品の状態
   5. タイトル・説明文: タイトルは `form_input` で入れる。説明文（textarea）は `form_input` だと空のままになることがあるので、`computer` でクリック→ `type` で入力する。入力済みの説明文を差し替えるときは、クリック→ `key` で `cmd+a Delete` → `type`
   6. 配送料の負担を「送料込み」、配送の方法を「らくらくメルカリ便」、発送までの日数を「4~7日で発送」にする。配送の方法は未選択（「配送の方法を選択する」）や別のものになっていることがあるので、その場合は開いて「らくらくメルカリ便」を選び「更新する」を押す。発送元の地域は既定値のまま。空欄なら Step 4 で聞いた値を `form_input` で選ぶ
   7. 価格
   8. 商品の特徴: 承認済みの値を入れる。プルダウンは `form_input`、メインカラーは別画面でチェックして「決定する」を押す
4. 入力後、`get_page_text` などで各項目の値を読み戻し、承認した内容と一致するか確かめる。ずれていれば直す
5. 承認内容に無い項目がフォームにあった場合（サイズ・色、「製品情報」「タレント名」「アイテム名」など、カテゴリによって出る項目）は、勝手に埋めずにユーザーに聞く

## Step 7: 引き渡し

```
出品画面に入力しました（タブ: 〇〇）。
- 入力した項目: 画像N枚 / カテゴリ / ... / 価格 ¥X,XXX
- 入力できなかった項目: （あれば理由つき）

内容を確認して、問題なければ「出品する」を押してください。
```

ここで止まる。「出品する」「下書きに保存する」は押さない。
