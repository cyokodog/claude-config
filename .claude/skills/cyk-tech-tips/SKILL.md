# cyk-tech-tips スキル

テキストまたはURLを受け取り、カテゴリ別のMarkdownファイルにtipsとして追記する。
自分で書いたメモ・知見・ノウハウ、またはURLから取得した概要を蓄積するスタイル。

## 実行形式

```
# カテゴリ自動提案
/cyk-tech-tips <テキストまたはURL>

# カテゴリ直接指定（確認なしで追記）
/cyk-tech-tips <カテゴリ名> <テキストまたはURL>
```

## 実行手順

### 1. 引数の解析

`$ARGUMENTS` を解析し、入力種別とモードを判定する。

**入力種別の判定（カテゴリ名除去後）:**
- `http` で始まるトークンがある → **URLモード**
- それ以外 → **テキストモード**

**カテゴリ指定の判定:**
- テキストモード: 最初のトークンが短い単語（1単語）でそれ以降にテキストが続く → 直接指定モード / それ以外 → カテゴリ提案モード
- URLモード: URLの前に単語がある → 直接指定モード / URLのみ → カテゴリ提案モード

判定が難しい場合はカテゴリ提案モードとして扱う。

### 2. コンテンツの取得

**テキストモードの場合:**
渡されたテキストをそのまま使用する。

**URLモードの場合:**
`WebFetch` ツールを使ってURLのページ内容を取得し、主題・特徴・キーワードを把握する。

### 3. カテゴリの決定

#### カテゴリ提案モードの場合

`ls ~/src/github.com/cyokodog/my-note/notes/my-tech-tips/` で既存カテゴリ一覧を取得する（`index.md` は除く）。

既存カテゴリの中から内容に合うものを優先して1〜3個の候補を選ぶ。既存カテゴリに適切なものがない場合のみ新規カテゴリ名を候補に加える。

```
カテゴリを提案します（既存: XXX, YYY）：
1. XXX（既存）
2. YYY（既存）
3. ZZZ（新規）

どれにしますか？番号で答えるか、別のカテゴリ名を入力してください。
```

ユーザーの回答を受けてカテゴリ名を確定する。

#### 直接指定モードの場合

引数の最初のトークンをカテゴリ名として使用する。確認は不要。

### 4. メモの生成

**テキストモードの場合:**

渡されたテキストから `## タイトル` と本文を抽出・整形して生成する：

```markdown
## {タイトル}

{テキストを整形した内容}
```

- テキストに `## タイトル` が含まれる場合はそのまま使用する
- タイトルがない場合は内容から推測して付ける
- 内容は適切に整形・簡潔化する

**URLモードの場合:**

取得したページ内容から数行の概要としてまとめる：

```markdown
## {ページタイトルまたは技術名}

{内容を数行で簡潔にまとめる。何ができるか・どんな特徴があるか・使いどころなど。}
[link]({URL})
```

- 詳細な要約は不要。「何者か」「何が特徴か」がわかる程度でよい

**共通: 補足情報の自動追加**

渡された情報は「ユーザーが知っている範囲」の断片的な情報であることが多い。以下の観点でAIが知識を補い内容を充実させる：

- **関連する選択肢・代替手段**: 言及されているのが選択肢の1つに過ぎない場合、同カテゴリの他の選択肢も列挙する
- **典型的なユースケース**: その技術・設定が実際に何に使えるか、代表的な活用例を補足する
- **注意点・ハマりどころ**: 既知の制限・よくあるミス・バージョン依存の注意点があれば追記する
- **公式・関連リンク**: 公式ドキュメント・GitHubリポジトリ・仕様ページなど参照すべきURLを末尾に `[テキスト](URL)` 形式で追加する

ただし補足はあくまで簡潔に。詳細な解説は不要で、「気づきのヒント」になる程度の粒度でよい。

### 5. カテゴリファイルへの追記

カテゴリファイルのパス: `~/src/github.com/cyokodog/my-note/notes/my-tech-tips/{カテゴリ名}.md`

**ファイルが存在する場合:**
`Read` ツールで既存内容を読み込み、末尾に追記して `Write` ツールで保存する。

**ファイルが存在しない場合:**
以下のフォーマットで新規作成する：

```markdown
# {カテゴリ名}

## {タイトル}

{内容}
```

### 6. index.mdの更新

`~/src/github.com/cyokodog/my-note/notes/my-tech-tips/` 内の `.md` ファイル（`index.md` を除く）をすべて `Read` ツールで読み込み、各ファイルから以下を抽出する：

- ファイル名（拡張子なし）→ カテゴリ名
- ファイルの内容全体からカテゴリのテーマを把握 → 説明文として使用

以下のフォーマットで `index.md` を `Write` ツールで上書き保存する：

```markdown
---
expanded: true
---

# cyk-tech-tips

| カテゴリ | 内容 |
|----------|------|
| [{カテゴリ名}](/#/notes/my-tech-tips/{カテゴリ名}.md) | {カテゴリの説明} |
| [{カテゴリ名}](/#/notes/my-tech-tips/{カテゴリ名}.md) | {カテゴリの説明} |
```

- カテゴリはアルファベット順に並べる
- 内容列はカテゴリファイル全体が「何についてのtipsか」を一言で説明する
- `##` エントリの個別タイトルを列挙するのではなく、カテゴリ全体のテーマを表す説明文にする

### 7. 完了報告

追記したカテゴリファイルのパスをユーザーに伝える。

## 注意事項

- `~/` は `/Users/cyokodog/` に展開して使用する
- 内容はすべて日本語で記述する
- カテゴリ名はファイル名になるため、日本語・スペースは避けてアルファベットまたはハイフン区切りにする
- 出力先ディレクトリが存在しない場合は `mkdir -p` で作成する
