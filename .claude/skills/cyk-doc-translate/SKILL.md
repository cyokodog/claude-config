# cyk-doc-translate

`cyk-doc-fetch` が保存した `en/`（英語原文）を日本語に翻訳し、`ja/` に保存するスキル。

**翻訳は「人間が読むため」のもの。** `cyk-doc-ask` は根拠として `en/` のみを読むため、
`ja/` は回答の根拠には使われない。したがって**必要なページだけ訳せばよい**。

全ページの一括翻訳は既定ではない。範囲を指定して使う。

## 手順

### Step 1: パラメータ解決

`$ARGUMENTS` から以下を抽出する。

- **`<name>`**: 対象ドキュメント名（`playwright` など）。省略時は Step 2 で解決する
- **ページ/カテゴリ指定**: `02-guides/03-routing.md`、`02-guides/`、`routing` のような指定。部分一致で解決してよい
- **`--all`**: 全ページを翻訳する。**トークン消費が大きいため、実行前に必ずページ数を提示して確認を取る**
- **`--force`**: `ja/` に既存ファイルがあっても訳し直す
- **`--dir <path>`**: 任意。ベースディレクトリ

**範囲指定が一切ない場合は、勝手に全訳しない。** `en/index.md` の一覧を提示し、どれを訳すか尋ねる。

### Step 2: 対象ドキュメントの解決

`cyk-doc-ask` と同じ探索規則を使う。

1. **`--dir <path>` の指定があれば**そのディレクトリ配下
2. **カレントディレクトリ配下** — `*/en/index.md` を探す
3. **既定のナレッジ置き場** — `~/src/github.com/cyokodog/cyk-knowledge/refs/*/en/index.md`

```bash
find . -maxdepth 3 -path "*/en/index.md" 2>/dev/null
ls -d ~/src/github.com/cyokodog/cyk-knowledge/refs/*/ 2>/dev/null
```

候補が複数あり推測できなければ、番号付きで提示して選択を求める。

### Step 3: 翻訳対象の確定

指定から対象ファイルを解決し、**既に `ja/` に存在するものを除外する**（`--force` 時を除く）。

```bash
# 未翻訳のページを洗い出す
cd <docroot>
for f in $(cd en && find . -name '*.md' ! -name 'index.md'); do
  [ -e "ja/$f" ] || echo "$f"
done
```

対象が複数ある場合は、翻訳前に件数を提示する。

```
翻訳対象: 3 ページ（うち 2 ページは翻訳済みのためスキップ）
  02-guides/03-routing.md
  02-guides/04-network.md
```

### Step 4: 翻訳

各ファイルを `en/` から読み、日本語に訳して `ja/` の**同じ相対パス**に保存する。

**翻訳ルール：**

- 本文・見出し・説明文を日本語化する
- コードブロック内のコードは翻訳しない（コメントは日本語化してよい）
- **API名・設定キー・クラス名などの識別子は翻訳しない**（原文表記を維持する）
- 原文の見出し構造・コードブロック・表を落とさない。**要約しない**
- ファイルヘッダーは以下の形式に変える：

```markdown
# <日本語タイトル> | <Site Name>

原文: <サイト上のページURL>
英語版: `en/<相対パス>`

<本文（日本語）>
```

`英語版:` を入れておくことで、訳文を読んでいて原文を確認したくなったときに辿れる。

### Step 5: ja/index.md の更新

**呼ばれ方によって扱いを変える。**

| 呼ばれ方 | index.md の扱い |
| -------- | --------------- |
| ユーザーが明示的に実行（`--all` やカテゴリ指定） | `ja/index.md` が無ければ `en/index.md` を基に全体を作成し、あれば翻訳済み行を更新する |
| `cyk-doc-ask` からの自動呼び出し（単一ページ） | **そのページの行だけを追記・更新する。全体の生成はしない** |

自動呼び出しで全体を生成すると、1ページ訳すだけで数十行分のトークンを消費してしまう。
`ja/index.md` が存在しない状態で自動呼び出しされた場合は、**ヘッダーと該当行だけの最小の index.md** を作る。

**Keywords 列は英語のまま維持する**（識別子は翻訳すると検索できなくなるため）。

未翻訳のページは一覧に含めてよいが、リンクを張らず未翻訳と分かるようにする。

形式：

```markdown
# <Site Name> ドキュメント（日本語版）

公式サイト: <root url>

<1-2行の概要説明（日本語）>

※ 未翻訳のページは `en/` を参照。翻訳するには `/cyk-doc-translate <name> <ページ>`

---

## <カテゴリ名（日本語）>

| ページ | ファイル | 概要 | キーワード |
| ------ | -------- | ---- | ---------- |
| [日本語タイトル](./path/to/file.md) | `path/to/file.md` | 概要説明（日本語、1-2文） | `apiName`, `configKey` |
| (未翻訳) Title | `path/to/other.md` | — | `apiName` |
```

### Step 6: 完了報告

```
## 翻訳完了

出力先: <docroot>/ja/
  02-guides/03-routing.md
  02-guides/04-network.md

翻訳済み: 12 / 71 ページ
```

**コミットはユーザーが行うため、スキル側では commit / push しない。**

## cyk-doc-ask から呼ばれる場合

`cyk-doc-ask` が回答の根拠にしたページが未翻訳だったとき、このスキルが自動的に呼ばれる。

その場合の扱い：

- **確認を取らずに、その参照ページだけを翻訳する**（範囲が1〜数ページに限られ、ユーザーが求めている内容と一致しているため）
- 翻訳後、`cyk-doc-ask` 側がその日本語本文を回答に添えて提示する
- **根拠はあくまで `en/` のまま。** 翻訳を根拠に使うと識別子の表記揺れが回答に混入する

## 注意

- **原文の取得はこのスキルの仕事ではない。** `en/` が無い場合は `/cyk-doc-fetch <url>` を案内して終了する
- `--all` は 71 ページ級のドキュメントでは非常に大きな消費になる。**必ずページ数を示して確認を取る**
