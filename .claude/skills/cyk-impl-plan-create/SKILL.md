# cyk-impl-plan-create

GitHub Issueの内容を実施可能なレベルまで具現化し、手順のぶれをなくすための実装計画をmdファイルに書き出す。

このスキルが担うのは計画の新規作成のみ。Step完了時の✅付けやaction-items的な残課題整理はスコープ外（別の関心事として扱う）。

## 手順

### 1. Issueの取得

`$ARGUMENTS` からIssue番号またはURLを解決する。指定がなければユーザーに確認する。

```bash
gh issue view <ISSUE_NUMBER> --json number,title,body,comments,url
```

タイトル・本文・コメントを読み込み、計画のインプットにする。

### 2. 出力先の決定

作業リポジトリのルートを基準に `docs/issues/<issue番号>/` を出力先とする。

- `docs/issues/` ディレクトリが存在すれば、そのまま `docs/issues/<issue番号>/` を使う
- 存在しなければ、出力先をユーザーに確認してから進める（別ディレクトリを使う可能性があるため）

### 3. 関連コードの調査

ステップ案を出す前に、Issueに関係するコードを実際に読む。実施のぶれをなくす粒度（ファイルパス・モジュール構成・設定ファイルのキー名などの具体名）は、Issueの文面からではなくコードから得られる。

- 変更対象になりそうなディレクトリ・ファイルの現状の構成を把握する
- 既存の類似実装（踏襲すべきパターン）があれば特定する
- 設定ファイル（wrangler.jsonc、package.json、環境変数など）への影響を確認する

### 4. ステップ骨子の合意

調査結果をもとに、まず全体のステップ分割案（Step 1〜Nの見出しと1〜2行の概要のみ）を提示し、ユーザーと合意する。個々のステップの詳細に入る前に全体像を固めることで、後からのステップ入れ替え・分割による書き直しを防ぐ。

### 5. 各ステップの具現化（ディスカッション）

合意した骨子に沿って、Step 1から順に詳細をユーザーと対話しながら詰める。

- 目的は「実施する際のぶれをなるべくなくす」こと。実施に本当に必要なことだけを明確化する
- 内容はファイルパス・関数名・設定キーなどの具体名で書く。「適切に修正する」のような抽象表現を残さない
- 背景・目的の説明、「やらないこと」の記載など、実施に直結しない体裁は書かない。簡潔な箇条書きで、実務的な手順のみを記述する
- 手作業が必要な項目（環境変数の設定、外部サービス側の設定変更など）もステップとして明記する
- 曖昧な点・複数の実装方針がありうる点は、都度ユーザーに確認してから確定する。確認せずに仮決めで進めない

### 6. 確定したステップから逐次ファイルに書き込む

1ステップが確定するたびに、ディスカッションの完了を待たずにその場でファイルに反映する（すべて確定してから一括で書き出さない）。

出力ファイルの構成は以下の基準で自動判断する：

- ステップ数が少なく各ステップの内容が簡潔（数行程度）に収まる場合 → `docs/issues/<issue番号>/index.md` 1ファイルにすべて書く
- ステップ数が多い、または個々のステップに調査結果・設計判断・コード構成など詳細な記述が必要な場合 → ステップごとに `docs/issues/<issue番号>/NN-<topic-slug>.md`（例: `01-schedule.md`）に分割し、`index.md` にはステップ一覧の要約（見出しと箇条書き数行程度）のみを書く
- ディスカッション中に後者の基準に該当すると判明した場合は、その時点でindex.mdのみの構成から分割構成に切り替えてよい

ファイルの体裁：

- 各ファイルの冒頭に対象Issueへのリンクを入れる: `対象Issue: [#<番号>](<Issue URL>)`
- 見出しは `## Step N: <タイトル>` 形式（分割ファイルの場合は `# Step N: <タイトル>` を先頭見出しにする）
- 内容は箇条書き中心。手順が一意に読み取れる粒度で書く

具体的な体裁は以下の実例を踏襲する：

```
# #19 実装計画

対象Issue: [#19](https://github.com/pxgrid/pxgrid-esa-agent/issues/19)

## Step 1: リファクタリング

- `src/agents/` をエージェントごとのサブディレクトリに変更
- `src/apis/` を新設し、plain API 関数を `src/tools/` から移動

## Step 2: 環境設定（手作業）

- KV namespace 作成 → `wrangler.jsonc` の `<KV_NAMESPACE_ID>` 差し替え
- Slack Bot に `channels:join` スコープ追加・再インストール
```

分割ファイル（`01-schedule.md`など）の場合は、index.md側の該当ステップは要約のみにし、詳細はファイルリンクで参照させる。
