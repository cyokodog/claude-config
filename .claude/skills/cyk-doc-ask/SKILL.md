# cyk-doc-ask

`cyk-doc-fetch` で保存したローカルドキュメントを**根拠**として参照し、出典を示しながら答えるスキル。

一般知識による推測を排し、「ドキュメントに何が書かれているか」に基づいた会話をするためのもの。

## 基本方針

1. **根拠は `en/`（英語原文）を読む** — API名・設定キー・エラーメッセージは原文にしか正確な形で存在しない。`ja/` は翻訳で表記が揺れるため根拠には使わない
2. **回答は日本語で書く**
3. **出典を必ず示す** — どのファイルを根拠にしたかを明示する
4. **書かれていないことは書かれていないと言う** — 一般知識で埋めない

## 手順

### Step 1: パラメータ解決

`$ARGUMENTS` は「質問文」と「オプション」が混在した1つの文字列として渡される。以下の順で解釈する。

1. `--dir <path>` があれば抽出し、`$ARGUMENTS` から**除去する**
2. 残った文字列全体を**質問文**として扱う
3. 残りが空なら、質問なしの起動（対象ドキュメントだけ確定して会話に入る）と見なす

例：

| `$ARGUMENTS` | 対象ディレクトリ | 質問文 |
| ------------ | ---------------- | ------ |
| `ルーティングの設定方法は？` | 既定の探索 | `ルーティングの設定方法は？` |
| `--dir ./docs ルーティングは？` | `./docs` | `ルーティングは？` |
| `(空)` | 既定の探索 | なし |

### Step 2: 対象ドキュメントの解決

**`--dir <path>` の指定がある場合：** そのディレクトリ配下を対象にする。

**指定がない場合：** 以下の順で探索する。

1. **カレントディレクトリ配下** — `*/en/index.md` を探す
2. **既定のナレッジ置き場** — `~/src/github.com/cyokodog/cyk-knowledge/refs/*/en/index.md` を探す

```bash
# カレント配下
find . -maxdepth 3 -path "*/en/index.md" 2>/dev/null

# 既定のrefs
ls -d ~/src/github.com/cyokodog/cyk-knowledge/refs/*/ 2>/dev/null
```

**候補の扱い：**

- **1件** → それを使う
- **複数件** → 質問文の内容から推測できればそれを使い、推測できなければ番号付きで提示して選択を求める
- **0件** → 「参照可能なドキュメントが見つかりません。`/cyk-doc-fetch <url>` で取得してください」と伝えて終了する

### Step 3: 対象の明示（必須）

対象が確定したら、**最初に必ず1行で表示する**。

```
対象: ~/src/github.com/cyokodog/cyk-knowledge/refs/playwright/en/
```

これにより、ユーザーが解決ミスにすぐ気付ける。また以降のターンで参照先がぶれるのを防ぐ。

### Step 4: 該当箇所の特定

1. **`en/index.md` を読む** — Description と Keywords 列から、質問に関係するページを絞り込む
2. **該当ファイルを `en/` から読む**
3. **index.md で当たりがつかない場合は grep にフォールバックする**（Keywords 列がない古い形式の index.md もあるため）

```bash
grep -rn "<検索語>" <docroot>/en/ | head -20
```

必要なら複数ファイルを読む。関連ページへのリンクがあれば辿る。

### Step 5: 回答

**回答ルール：**

1. **出典のパスを必ず示す** — `en/02-guides/03-routing.md` のように、docroot からの相対パスで書く
2. **原文引用は軽量に** — 毎回引用ブロックを付ける必要はない。以下の場合のみ原文を `>` で引用する
   - 仕様を**断定**するとき（「〜は必ず〜になる」など）
   - API シグネチャ・設定キーの正確な表記を示すとき
   - ユーザーが原文を求めたとき
   - 解釈に幅があり、原文を見せたほうが早いとき
3. **記載がない場合は明言する** — 「ドキュメントに記載がありません」と言う。推測で埋めない
4. **一般知識を補足する場合は明示する** — どうしても補足が必要なら `※ドキュメント外の一般知識` と明記して区別する

**回答の形：**

```
<回答本文（日本語）>

> <原文引用（断定時のみ）>

出典: `en/02-guides/03-routing.md`
```

複数ファイルを根拠にした場合は全て列挙する。

### Step 6: 会話モードの維持

**このスキルは1問1答で終わらない。** 以降の会話でも、対象ドキュメントに関する質問には
Step 4〜5 のルール（en/ を読む・出典を示す・記載がなければ記載なしと言う）を**維持し続ける**こと。

対象ドキュメントを切り替えたい場合は、ユーザーが再度 `/cyk-doc-ask --dir <path>` を実行するか、
別のドキュメントについて明示的に尋ねたときに Step 2 からやり直す。

## 注意

- **メインセッションの文脈は活かしてよい** — 「今書いているコードに照らしてどうか」のような質問には、
  ドキュメントを根拠にしつつプロジェクトの文脈を踏まえて答える。文脈を捨てる必要はない
- **ただし文脈とドキュメントを混ぜない** — ドキュメントに書かれていることと、
  プロジェクト固有の事情や一般知識は、回答の中で区別できるように書く
