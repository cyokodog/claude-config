# cyk-tech-memo スキル

技術記事のURLを受け取り、カテゴリ別のMarkdownファイルに短いメモとして追記する。
1記事あたり数行の広く浅い情報を蓄積するスタイル。

## 実行形式

```
# カテゴリ自動提案
/cyk-tech-memo <url>

# カテゴリ直接指定（確認なしで追記）
/cyk-tech-memo <カテゴリ名> <url>
```

## 実行手順

### 1. 引数の解析

`$ARGUMENTS` を解析し、以下のどちらのパターンかを判定する：

- **URLのみ**: 最初のトークンが `http` で始まる → カテゴリ提案モード
- **カテゴリ名 + URL**: 最初のトークンが `http` で始まらない → 直接指定モード

### 2. 記事内容の取得

`WebFetch` ツールを使って指定URLのページ内容を取得する。
主題・キーワード・特徴的な情報を把握する。

### 3. カテゴリの決定

#### カテゴリ提案モードの場合

`ls ~/src/github.com/cyokodog/my-note/notes/my-tech-memo/` で既存カテゴリ一覧を取得する（`index.md` は除く）。

既存カテゴリの中から内容に合うものを優先して1〜3個の候補を選ぶ。既存カテゴリに適切なものがない場合のみ新規カテゴリ名を候補に加える。

```
カテゴリを提案します（既存: XXX, YYY）：
1. XXX（既存）
2. YYY（既存）
3. ZZZ（新規）

どれにしますか？番号で答えるか、別のカテゴリ名を入力してください。
```

ユーザーの回答を受けてカテゴリ名を確定する。

#### 直接指定モードの場合

引数の最初のトークンをカテゴリ名として使用する。確認は不要。

### 4. メモの生成

以下のフォーマットで生成する：

```markdown
## {記事タイトルまたは技術名}

{主要な情報を2〜4文で記述。何ができるか・どんな特徴があるか・使いどころなど。}
[link]({URL})
```

- 詳細な要約は不要。「何者か」「何が特徴か」がわかる程度でよい
- 箇条書きより文章で書く
- スペック・数値など具体的な情報があれば含める

### 5. カテゴリファイルへの追記

カテゴリファイルのパス: `~/src/github.com/cyokodog/my-note/notes/my-tech-memo/{カテゴリ名}.md`

**ファイルが存在する場合:**
`Read` ツールで既存内容を読み込み、末尾に追記して `Write` ツールで保存する。

**ファイルが存在しない場合:**
以下のフォーマットで新規作成する：

```markdown
# {カテゴリ名}

## {記事タイトルまたは技術名}

{メモ}
[link]({URL})
```

### 6. index.mdの更新

`~/src/github.com/cyokodog/my-note/notes/my-tech-memo/` 内の `.md` ファイル（`index.md` を除く）をすべて `Read` ツールで読み込み、各ファイルから以下を抽出する：

- ファイル名（拡張子なし）→ カテゴリ名
- ファイルの内容全体からカテゴリのテーマを把握 → 説明文として使用

以下のフォーマットで `index.md` を `Write` ツールで上書き保存する：

```markdown
---
expanded: true
---

# cyk-tech-memo

| カテゴリ | 内容 |
|----------|------|
| [{カテゴリ名}](/#/notes/my-tech-memo/{カテゴリ名}.md) | {カテゴリの説明} |
| [{カテゴリ名}](/#/notes/my-tech-memo/{カテゴリ名}.md) | {カテゴリの説明} |
```

- カテゴリはアルファベット順に並べる
- 内容列はカテゴリファイル全体が「何についてのメモか」を一言で説明する
- `##` エントリの個別タイトルを列挙するのではなく、カテゴリ全体のテーマを表す説明文にする

### 7. 完了報告

追記したカテゴリファイルのパスをユーザーに伝える。

## 注意事項

- `~/` は `/Users/cyokodog/` に展開して使用する
- メモはすべて日本語で記述する
- カテゴリ名はファイル名になるため、日本語・スペースは避けてアルファベットまたはハイフン区切りにする
- 出力先ディレクトリが存在しない場合は `mkdir -p` で作成する
