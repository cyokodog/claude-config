# リーバイス型番ノート育成スキル

リーバイスの型番ごとのノートに、サンプル画像と、古着としての読み物を足す。510.md で作った形を、ほかの型番にも同じように広げるためのスキル。

## 対象

```
~/src/github.com/cyokodog/my-note/notes/_interest/clothing/denim/levis/
  index.md          型番一覧
  models/<型番>.md   型番ごとのノート（対象）
  models/assets/     画像置き場
  topics/           横断的な話題
  sources.md
```

手本は `models/510.md`。作業前に必ず読み、見出しの立て方・語り口・出典の書き方を合わせる。

### ノートの構成

型番ノートは次の構成にする。既存のノートがこの形になっていなければ、この形に整える。

```md
# <型番>

> 一覧に戻る: [リーバイスの型番](../index.md)

## 概要
（古着と現行の違い、呼び名、系統を数行で）

## 年代別

### <系統や年代>(<期間>)
（画像。事実の箇条書き。採寸の表）

### 現行 <名前>(<期間>)

## 古着の<型番>

### <中身が分かる見出し>
（読み物）

## 古着で探すときのチェックリスト

## 関連する型番

## 動画

## 出典
```

- `## 概要` と `## 年代別` は事実を短くまとめる場所、`## 古着の<型番>` は読み物の場所として分ける。読み物で分かったこと（呼び名、時期、当時の売られ方など）は、概要と年代別にも事実として反映する
- 年代別の `###` は、中身に合った名前にする。「80s」と書いて90年代の個体が中心、のようなずれを作らない。赤タブとオレンジタブのように系統が分かれるなら、系統ごとに `###` を立てる
- 採寸の表は cm（平置き）にそろえ、列は「製造 / タグ表記 / ウエスト / 股上 / わたり / 裾幅 / 股下 / 裾上げ / 価格 / 出典」にする。価格は調べた日付を表の説明に書き、売り切れなら「(売り切れ)」を付ける。股下は裾上げか縮みかの判断に使うので必ず列を作る。「裾」には裾上げなし・裾上げあり・不明を書く。わからない値は「—」。メンズの参考にするため W30 以上を中心にし、W29 以下は裾上げされていないと分かるものだけ載せる
- 表の行は製造の古い順に並べる（同じ月なら週の早い順）。製造年月は内タグから読んで埋める
- 表の下に、表から言えること（タグと実寸の差、裾幅とわたりの比など）を短くまとめる
- `## 古着で探すときのチェックリスト` は、品番の表記・製造国・ボタン裏の刻印・パッチ・袋布の印刷・タグの L と実際の股下の差などを、その型番に合わせて並べる。`- [ ]` はビューアーでクリックするとファイルが書き換わるので使わず、普通の箇条書きにする
- `## 関連する型番` は、兄弟モデル・比較される型番・番号だけ同じ別モデルを並べる
- ページ内リンク（`#…`）はビューアーで動くか確かめていないので使わず、「〜を参照」と文章で案内する
- `## 古着の<型番>` は `## 年代別` の後（現行の `###` の後）に置く。年代別の中に入れない

## 鉄則

- **画像はユーザーが指定したページから取る。** 自分で見つけたページの画像を勝手に使わない。候補を見つけたら URL を示して、使ってよいか聞く。
- **画像は元ページへのリンクにし、`## 出典` にも「画像: …」として載せる。** URL の追跡用パラメータ（`?srsltid=…` など）は外す。
- **my-note のアプリのコード（`components/` など）は勝手に変えない。** 表示がおかしいときは原因を説明し、直し方を提案して指示を待つ。
- **推測で書かない。** 出品者の説明・個人の記憶・1店だけの記述は、本文でもそれと分かる書き方にする（「〜とのこと」「裏付けは見つかっていない」）。自分の推測で段落を締めない。
- **出品名の年代を信じない。** 写真で確かめられることは写真で確かめる（「年代の見分け方」を参照）。
- **コミットしない。** 書き終えたら止まって、どこを変えたかを報告する。

## 情報取得の共通方針

検索、ページ本文・HTML・公開データ、画像の通常取得を先に使う。必要な情報が取得できていればブラウザは使わない。不足した場合だけ `~/src/github.com/cyokodog/claude-config/.claude/shared/cyk-browser-operations.md` の共通入口を目的 `research` で呼び、Playwright MCPで追加確認する。このスキルのブラウザ操作にClaude in Chromeは使わない。

不足の原因をJavaScriptやログインと決めつけず、取得できた情報と不足している項目を確認して判断する。必要な範囲だけ読み、同じページ全文やスナップショットの取得を繰り返さない。権限による拒否やログイン要求は迂回せず、読めない項目を報告する。

## 流れ

```
Step 1 対象の型番ノートを読む
Step 2 画像を作って貼る（ユーザーが URL を指定した場合）
Step 3 調べる（サブエージェント → ブラウザで深掘り → メルカリで採寸 → YouTube）
Step 4 読み物「## 古着の<型番>」を書く
Step 5 動画の節と出典を整える
Step 6 報告して止まる
```

画像だけ、読み物だけ、と頼まれたら該当する Step だけ行う。

## Step 1: 対象の型番ノートを読む

- `models/<型番>.md` と手本の `models/510.md` を読む
- ノートが無い型番なら、新しく作るかユーザーに聞く（`models/index.md` への追加も必要になる）
- 既存の `## 年代別` の見出し（`### 80s(…)` など）を確認し、画像や読み物をどこに入れるか決める

## Step 2: 画像を作って貼る

### 画像を取る

ユーザーが指定したページの写真を、scratchpad の作業用ディレクトリ（ページごとに新しい空のディレクトリ）に落とす。

- **メルカリ**: 公開ページから画像URLを確認して写真を直接取得する。通常取得で不足する場合だけ共通入口で追加確認する（3-3 を参照）
  `https://static.mercdn.net/item/detail/orig/photos/<商品ID>_<n>.jpg`（n = 1, 2, 3 …。404 になったら終わり）
- **eBay**: 公開ページのHTMLなどから `i.ebayimg.com/images/g/<ID>/` のIDを集める。通常取得で見つからなければ共通入口で追加確認する。
  `https://i.ebayimg.com/images/g/<ID>/s-l1600.jpg` で大きい画像が取れる
- **BASE などのショップ**: HTML を curl して画像 URL を拾う
- 取った写真は縮小した一覧（コンタクトシート）にまとめて Read で見て、正面・バック・パッチの写真を選ぶ

ユーザーが会話に貼った画像は、どの写真かの手がかりとして使う。

### 画像を組む

正面・バック・パッチ（紙パッチや赤タブのアップ）の3コマを横に並べた1枚にする。

```bash
python3 -I ~/.claude/skills/cyk-levis-model-note/scripts/make_panels.py \
  <scratchpad>/out.jpg \
  <正面.jpg> <バック.jpg> <パッチ.jpg>:x0,y0,x1,y1
```

- 1コマ 326×500、3コマで 998×500。高さ 500 はユーザーが選んだサイズ
- 切り抜き範囲を省略すると、縦横比 2:3 で中央を切り抜く。ジーンズが切れる・パッチがずれるときは `:x0,y0,x1,y1` で直す（2:3 に近い範囲にする）
- できた画像は必ず Read で見て確かめてから配置する

### 配置する

- 置き場所: `models/assets/<型番>_<区別>.jpg`（例: `510_80s.jpg`、`510_orange.jpg`）
- 本文: 該当する見出しの直下に、画像を元ページへのリンクにして貼る

```md
[![510(80s)](./assets/510_80s.jpg)](https://jp.mercari.com/item/m50665642673)
```

- `## 出典` の先頭側に `- [画像: <商品名など> - <サイト名>](<URL>)` を足す
- 画像を差し替えたときは、古い画像ファイルを消し、リンクと出典も入れ替える

## Step 3: 調べる

### 3-1. サブエージェントで下調べ

general-purpose のサブエージェントに、次をまとめて調べさせる（日本語・英語の両方）。

- 事実: 製造時期、品番の後ろ4桁（0217 など）の意味、生地、ジッパー、パッチ、タブ、製造国と工場（ボタン裏の番号）、シルエット、近い型番との違い、廃番の時期と理由、品番の使い回し、染料・色落ち・色味の特徴（製造国や年代による違いの説も含む）
- 相場と人気: 国内の古着店・ヤフオク・メルカリ、Etsy・Grailed・eBay
- 人の意見・感想: ブログ、古着店の説明、フォーラム

指示に入れること: 出典 URL を必ず付ける／作り話をしない／不確かな点・ソース同士の食い違いを分けて書く／日本語で 1500〜3000 字にまとめる。

サブエージェントは検索と通常取得だけで下調べする。ブラウザでの追加確認はメインのエージェントが行い、同じページを並行操作しない。

### 3-2. 不足した情報を追加確認する

下調べで得た情報を目的と照合する。必要な内容が欠けていれば、まず通常取得で補い、それでも不足した項目だけ共通入口の `research` で選ばれるPlaywright MCPを使って確認する。

- 検索結果、出品ページ、古着店の説明、動画の説明・文字起こし・コメントなどを対象にする。サイトごとに読めると決めつけず、その時点の取得結果で判断する
- ログインが必要なら接続先と状態を確認する。認証や権限で読めなければ、その項目を未確認として報告する
- 出品ページの説明は `fetch` で HTML を取り、`meta[name="description"]` を読むと速い（Poshmark など）
- 調べ終えたタブは閉じる

### 3-3. メルカリで採寸例を集める

採寸の表を充実させる。メンズの参考にするため、W30以上を中心に集める。W29以下は裾上げされていないと分かるものだけ載せる。

- 検索: `https://jp.mercari.com/search?keyword=<キーワード>&status=on_sale`（例: 「levis 510 usa」「510-0217 裾上げなし」）。公開ページのHTMLや本文から商品名・URLを集め、情報が不足する場合だけ共通入口で表示内容を確認する。必要な候補に絞って商品ID・商品名・出典URLを記録する
- ユーザーのお気に入り（`https://jp.mercari.com/mypage/favorites`）を参照する場合は、共通入口でログイン状態を確認して候補を集める。利用可能ならここを優先する。Playwright専用プロファイルが通常のChromeのログインを引き継ぐと仮定しない
- タグの L は L34 に偏りやすい。L31・L32・L33 なども意識して集める（L ごとの股下の違いを見るため）
- 商品ページ: まず通常取得で説明文・採寸・コメントを確認する。不足する場合は共通入口でページを開き、内容が表示されたことを確認して必要な説明・該当コメントだけ読む。出品者が股下などをコメントで答えていることがある
- 調査済みのページと結果は作業メモへ記録し、同じページの読み直しを避ける。共有ブラウザの操作は直列で行う
- 価格はブラウザを使わず curl で取れる。商品ページの HTML の `<meta property="product:price:amount" content="3500">` を読む。売り切れかどうかは HTML からは見分けられないので、売り切れの検索結果（`status=sold_out`）で見つけたものだけ「売り切れ」とする
- 説明文が不足する場合は原因を断定せず、表示状態を確認して1回だけ追加確認する。それでも読めなければ未確認として記録する
- 採寸が写真だけの出品は、写真を curl で取って読めば使えるが手間がかかる。説明文に採寸がある出品を優先する
- 説明文にタグの L や製造年月が無くても、写真の紙パッチ・サイズタグ（「W32 L34」）・内タグ（「525 1292 …」）で読めることが多い。表に載せる行は、写真を全部取ってコンタクトシートで見て、タグの写真を拡大して読み、空欄を埋める。読み取った値であることを表の説明に書く
- 集めた値は scratchpad のメモに書きためてから表にする。製造年月（内タグの読み）、タグ表記、ボタン裏の刻印、裾上げの有無の記載、リベットの緑青の有無も一緒に控える
- 表から言えること（タグと実寸の差、裾幅とわたりの比など）を、表の下に短くまとめる。チェックリストの目安もそれに合わせて直す

### 3-4. YouTube

日本語で型番を検索する（例: 「リーバイス 510 古着」「リーバイス510 USA製 90年代」「510 ダッドジーンズ」）。動画ごとに次を読む。

- **説明欄と日付・再生回数**
- **文字起こし**: 通常取得で利用可能な字幕・文字起こしを確認する。不足する場合だけ共通入口で「文字起こしを表示」などを操作し、対象の型番に関係する箇所を読む。タイムスタンプや出典の位置は作業メモに残し、全文を何度も取得しない
- **コメント欄**: 通常取得で不足する場合だけ共通入口で必要なコメント・返信を表示し、本文と評価などの関連情報を取る。調査対象に関係するものを優先し、無制限にスクロールして集めない
- 動画を再生しっぱなしにしない（`video.pause()`）
- ナレーションもコメントも無い動画は、リンクだけ載せる

## Step 4: 読み物「## 古着の<型番>」を書く

### 置き場所と見出し

- 「ノートの構成」のとおり、`## 年代別` の後、`## 古着で探すときのチェックリスト` の前に `## 古着の<型番>` を置く
- 中は内容に合わせて `###` で分ける。510 の例:

```
## 古着の510
### 公式の記録がない型番
### 0217は510だけの番号ではない
### 細いのか、普通なのか
### 誰が穿くジーンズか
### 当時を知る人、いま穿く人
### オレンジタブの510
### 値段と、集める楽しさ
```

見出しは中身が分かる言葉にする。「詳細」「概要」のような見出しにしない。型番ごとに語れることは違うので、510 の見出しをそのまま使い回さない。

### 書き方

- です・ます調。箇条書きは、意見を並べるときや写真から読み取れることを並べるときに使い、地の文は段落で語る
- 人の意見・感想を入れる。引用は短くし、出典を本文中のリンクで示す（例: `([biscco](https://…))`）
- 意見が割れているときは両方書く
- 古着の世界で「よく言われる説」（例: ユーロリーバイスは、アメリカで使えなくなった染料を使い続けたので色落ちが深い）は、裏付けが1件しかなくても外さない。外す前に追加で検索して出典を増やし、伝聞であること・資料での裏付けがないことを添えて載せる
- 出品者の説明・個人の記憶・1店だけの記述は、伝聞であることが分かる書き方にする
- 最後の `###` は、その型番の魅力や位置づけで締める

### 年代の見分け方（出品名をうのみにしない）

- **ポケットの袋布**に「For over 140 years」「MADE OF PROGRESS」などの印刷 → 2013年以降の新しい製品（1873年の創業から140年）
- **オレンジタブ**: 2017年に Orange Tab シリーズが復活しているので、オレンジタブ＝古いとは限らない
- **紙パッチ・洗濯表示タグ・ボタン裏の番号**を写真で確かめる。読めないときは「読めない」と書く
- **裾上げ**: テーパードの型は、裾を切ると細い部分がなくなりストレートに見える。股下が極端に短い個体でシルエットを語らない。裾上げされていない個体は少ないので、見つけたら貴重な資料になる
- **裾上げの判定（タグの L と実寸の股下の差）**: 裾上げされていないジーンズは、縮んでもタグより2〜3%短い程度（ユーザーの手持ち: 511 L32 = 78.5cm、505 L32 = 80cm）。差が5%以下なら「なし(推定)」、8%以上なら「あり(推定)」とし、表には差の%も書く。510 の L33・L34 はほぼすべて8〜19%短く、裾上げされていた。出品者が「裾上げなし」と書いていても、差が大きければその旨を添える
  - 裾のアタリが弱ければ、最近の裾上げ。アタリが強くても、昔の裾上げのことがある
  - 裾幅とわたりの比は、裾上げした個体では裾上げした位置の値になる。本来の裾幅はもっと細い
- **品番の頭の「W」は女性用**: 「W510-0217」「W515-0217」など。メンズの参考にする表では、W 付きの個体はタグ表記に「女性用」と書く。ぼやけた写真では「W」が「4」に見えることがあるので、出品者の記載と照らし合わせる。頭が「4」の5桁品番（40511、40519、40547 など）は男性用の出品もあり、女性用とは限らない
- **内タグの製造年月**: 工場番号（例: 「525」）の後ろの数字で読める。510 で写真から確かめた範囲では2つの書き方があった
  - 4桁の「月月年年」: 「525 1292」= 1992年12月。出品者の書いた年と合っていた
  - 3桁の「週週年」: 頭の2桁が週番号、最後の1桁が年の下1桁。「525 189-…」= 1989年の第18週(5月初め)。月と読むと「189」が18月になってしまうので週と読む。表には「1989年5月(525、第18週)」のように週も書く
  - 1991〜92年ごろに3桁から4桁に変わったらしい。公式資料での裏付けはないので、本文では「タグからの読み」として書く

## Step 5: 動画の節と出典を整える

- `## 関連する型番` の後、`## 出典` の直前に `## 動画` を作る
- 動画1本ごとに、タイトルの `###`、その場で見られる iframe、別タブで開くリンクをセットにする

```md
### <動画タイトル>

<iframe width="560" height="315" src="https://www.youtube.com/embed/<動画ID>" title="<動画タイトル>" frameborder="0" allow="accelerometer; clipboard-write; encrypted-media; gyroscope; picture-in-picture; web-share" allowfullscreen></iframe>

<チャンネル名>(<年>年) / <a href="https://www.youtube.com/watch?v=<動画ID>" target="_blank" rel="noopener">YouTubeで開く</a>
```

- iframe は1行で書き、前後に空行を入れる（marked が HTML ブロックとして通す）
- 別タブで開くリンクは Markdown のリンクでは書けないので、`<a target="_blank">` で書く
- 埋め込みが許可されているかを先に確かめる。`https://www.youtube.com/oembed?url=https://www.youtube.com/watch?v=<動画ID>&format=json` が 200 なら埋め込める。401 などのときは iframe を使わず、リンクだけにする
- 本文で使ったページは、すべて `## 出典` に載せる。画像の元ページは「画像: …」として先頭側に置く
- 型番ノートの `## 概要` や年代別の箇条書きと、読み物の内容が食い違っていないか見直す
- 型番一覧（`levis/index.md`）の該当する行も、分かったことに合わせて直す（呼び名、時期、系統など）。Claude アプリなどが以前に書いた記述も、調べた結果と食い違っていれば直す

## Step 6: 報告して止まる

ユーザーに次を伝えて止まる。コミットはしない。

- どのファイルの、どの見出しに、何を足したか（行番号つきで）
- 調べたけれど読めなかったもの・確かめきれなかったこと
- ユーザーに判断してほしいこと（足すか迷った話など）

## 出品について意見を求められたとき

ユーザーが出品の URL やスクリーンショットを貼って「これどう？」と聞いてきたら、ノートは書き換えず、意見だけ返す。

1. 写真を全部取って見る（メルカリなら `static.mercdn.net` から n = 1, 2, … を curl。コンタクトシートで全体を見てから、タグ・パッチ・裾・採寸の写真を拡大して読む）
2. 本物か・年代: 内タグの品番と製造年月、ボタン裏の刻印、製造国、パッチ、タブ、袋布の印刷
3. 状態: 黄ばみ・破れ・パッチの傷み。説明文に別の商品の文章が混ざっていないか（コピペの使い回しはよくある）。リベットに緑青（青緑色の錆）が出ているかも見る。出ている個体は少なく、ユーザーが好む特徴なので、あれば良いところとして挙げる
4. サイズとシルエット: 採寸をノートの採寸の表と比べる。タグと実寸の差、裾のアタリ、写真で見たテーパー、裾幅とわたりの比から、裾上げか縮みかを考える。股下が短いだけで裾上げと決めつけない
5. 値段: ノートや調べた相場と比べる
6. 結論を先に言い、良いところ・気になるところを分ける

出品者は来歴（裾上げの有無、乾燥機の履歴など）を把握していないことが多い。質問を勧めるなら、その場で測れること（裾幅、ひざ幅、股上）や写真の追加（裾のステッチの拡大）にする。
