# git / gh

## 管理から外したファイルが、ブランチを切り替えると古い内容で上書きされる

- ブランチ A で `git rm --cached <file>` して `.gitignore` に入れると、手元のファイルは「管理外かつ無視」になる。
- その状態で、まだ `<file>` を管理しているブランチ（マージ前の古い main など）に切り替えると、git は無視されたファイルを捨ててよいものとみなし、**警告なしに古い内容で上書きする**。
- `gh pr merge --delete-branch` は、マージ後に手元を既定のブランチに切り替えて pull する。この切り替えでも同じことが起きる。
- 実例: 実行時の状態ファイル（キューの JSON）を管理から外す PR をマージしたとき、手元の最新の状態が古い main の内容で上書きされ、履歴が失われた。

対策:

- 管理から外すファイルがある PR では、マージの前に手元のファイルをバックアップする（`cp <file> <file>.bak` など、管理外の場所へ）。
- 手元の切り替えは、古い main を経由せず `git fetch && git checkout -B main origin/main` で新しい main に直接移る。`gh pr merge` には `--delete-branch` を付けず、切り替えを自分でやる。
