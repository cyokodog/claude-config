## 自動モード（auto）で `gh pr merge` が止められる

- 自動判定が「レビューなしのマージ」として拒否する。拒否された後は、同じ目的の別コマンド（`gh pr list` など）も止められることがある。
- 個人 PJ でマージまで自動で回すなら、`~/.claude/settings.json` の `permissions.allow` に `Bash(gh pr merge:*)` を入れておく。

## 自動モードで止められやすい操作（2026-10-29、cyk-mercari-post）

- コミット・PR・マージ・本番の再起動を1つのコマンドにまとめると止められる。ユーザーの了承を得てから、マージと再起動を別々に流すと通った（了承は PR 本文にも書いた）。
- マージ済みブランチの削除（`git branch -D`・`git push --delete`）は「取り消せない Git の操作」として止められる。ユーザーに `!` 付きのコマンドを渡して実行してもらう。
- 止められたら、同じ目的を別の形で続けない。何を止められたかと、今の状態を伝えて判断を仰ぐ。

## 長いセッションと引き継ぎ（2026-10-29、cyk-mercari-post）

- トークンの消費は、モデルより会話の長さで大きく増える。段階の区切りで新しいセッションに分け、設計の文書を最初に読ませる。
- 引き継ぎ文には手順だけでなく、計算・判断の注意（なぜそうするか、何を間違えやすいか）も入れる。入れ忘れて、別のセッション（Sonnet）が既知の落とし穴（期間を外れ値込みの最大−最小で出す）を踏んだ。注意はナレッジやスクリプトに固め、引き継ぎ文からそこを指す。
- AI に流れ全体を統括させない。状態と進み具合はアプリ（データ）に持たせ、AI には答えの形を決めた小さな判断だけを任せる。AI に計算させず、プログラムで計算する。
- AI はモデルを切り替えられない。使い分けは文書に「AI がユーザーに知らせること」として書く（例：決まった手順は Sonnet、計画・判断は Opus）。
