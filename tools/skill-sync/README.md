# スキル同期

Claude Code側の `.claude/skills/` を原本として、Codexのプロジェクト用探索先 `.agents/skills/` を構成する。Python 3.9以上、外部パッケージ不要。AIが定義を変更した作業の最後に実行する。常駐監視やスケジューラーは使わない。

初版の範囲はこのリポジトリのスキル同期。ユーザー共通の探索先へのインストール、エージェント変換、権限・モデル・MCP設定の変換は含めない。別プロジェクトでも使うためのユーザー共通インストールは次の段階で行う。既存の `.codex/agents/` は変更しない。

## AIが変更後に行うこと

1. 原本を編集する。Codexだけに必要な変更は `overrides/` に置く。
2. 新規・改名したスキルを `config.json` に分類する。削除した原本の項目は設定からも削除する。
3. `overlay` 対象の原本が変わったら差分を見直し、`source_digest` を更新する。
4. 次の確認・適用・再確認を行い、除外や失敗があれば完了報告に含める。

```bash
python3 tools/skill-sync/sync.py check
python3 tools/skill-sync/sync.py apply
python3 tools/skill-sync/sync.py check
```

別のディレクトリで作業していても、スクリプトを絶対パスで呼べばリポジトリを自動特定する。`check` は読み取りのみ。終了コードは 0＝同期済み、1＝適用待ち、2＝要対応／エラー。未分類や衝突があれば `apply` は出力を変更しない。既知の `exclude` は理由を表示し、エラー扱いにしない。

AIへの自然言語の指示で実行を促す仕組みであり、OSやフックによる強制実行ではない。

## 設定

`config.json` のキーは原本のディレクトリ名。新規スキルを無条件に公開しない。原本には大文字の `SKILL.md` が必要。

- `link`：原本ディレクトリにリンクする。本文・補助ファイルの変更は直接反映される。AIは変更時に引き続き互換性を確認する。
- `overlay`：原本をコピーし、`overrides/<name>/` のファイルを上書きする。原本の相対的なファイル構造を維持する。差分側は必要なファイルだけ管理する。本文の部分パッチではなくファイル単位の差し替えなので、原本更新時はAIが内容を統合する。
- `exclude`：理由を記録してCodexには出力しない。対応を見送ったものを成功したスキルとして報告しない。

`overlay` の項目には原本全体の `source_digest` を登録する。原本が変わると、差分が古いまま再生成されるのを防ぐため適用を止める。ハッシュは同ディレクトリの `sync.py` が提供する `digest(Path(...))` で取得できる。`link` は内容の完全な互換性や外部ツールの存在を保証する分類ではない。

モデル名・製品名・パス・ツール名の全体置換はしない。特に `.claude/shared/` や既存ナレッジはそのまま参照する。Claude固有の権限設定、Task API、CLI、ブラウザ操作をCodexでも動くと仮定しない。frontmatterは原本を保持するが、権限や自動起動を制御する項目が同じ意味で解釈されることは保証しない。各製品の承認規則を優先する。

## 所有権と復旧

`.agents/skills/` は出力先で直接編集しない。管理対象と生成時の内容を `.skill-sync/state.json` に記録し、手編集は上書きせずエラーにする。管理外の既存出力も通常は変更しない。他由来の `cyk-` 以外の項目は処理しない。

初回だけ、既存出力を読み比べたうえで以下を実行できる。

```bash
python3 tools/skill-sync/sync.py apply --adopt-existing
```

既存出力や更新前の出力は `.skill-sync/backups/` に移動して保存する。除外対象の既存コピーも退避される。古い出力は削除しない。元のコピーが必要なら対応するバックアップを確認する。バックアップと状態はGit管理外なので、クローンには含まれない。元の `AGENTS.md` は初回移行時に `.skill-sync/bootstrap/` に保存した。

`apply` は同時実行をロックし、検査後の出力変更も確認する。複数スキル全体の更新は単一トランザクションではないため、途中失敗したら出力・バックアップ・状態を確認して再実行する。Gitのコミット・プッシュは行わない。

`.agents/skills/` の出力自体はGit管理可能。リンク先が絶対パスなので、別マシンでは設定を確認してから再生成する。状態がないクローンでの再導入も、出力を確認してから `--adopt-existing` を使う。

## テスト

```bash
python3 -m unittest discover -s tools/skill-sync/tests -v
```

色ピッカーのテストは検証用のループバックHTTPサーバーを起動する。ポート待受けが制限される環境では、通常の承認手続きを使って実行する。実際のiTerm色設定は変更しない。

原本の変更は、既存のClaude Code用ホームリンクからも参照される。定義の追加・削除時は `CLAUDE.md` のClaude側リンク維持手順も実施する。
